# Humanize Korean (한글 AI 티 제거 및 윤문)

AI가 쓴 한글 텍스트에서 번역투, 기계적 병렬, 어색한 관용구, 이중 피동, 과도한 접속사, 리듬 균일성 등 10대 카테고리(70개 세부 패턴)의 AI 티를 탐지하고, 내용은 100% 보존하면서 자연스러운 사람 글처럼 윤문합니다.

## 언어 및 대상

- **언어**: 한국어 전용
- **목적**: 번역투 및 AI 글투 개선 (단순 맞춤법 검사나 새로운 내용 창작이 아님)

## 4대 철칙 (위반 시 즉시 롤백)

1. **의미 불변 (Fidelity First)**: 사실, 주장, 수치, 날짜, 고유명사, 직접 인용문은 원문과 100% 일치해야 합니다.
2. **근거 기반 (Span-Grounded)**: 룰북에 매핑되는 탐지 구간에만 수술적 수정을 가합니다. 탐지 없는 구간은 원형을 보존합니다.
3. **장르 유지 (Tone Match)**: 칼럼을 문학으로, 리포트를 에세이로 바꾸지 않습니다. 원문의 목적과 톤앤매너를 유지합니다.
4. **과윤문 금지 (Change Rate Limit)**: 변경률 30% 초과 시 경고, 50% 초과 시 강제 중단 및 롤백합니다.
5. **Do-NOT**: 고유명사, 제품명, 기관명, 수치/단위, 큰따옴표 안 직접 인용, 법률 조문, 영어 기술 약어(LLM, GPU, API 등)는 원형을 보존합니다.
6. **Register(격식) 보존**: 원문이 격식체면 결과도 격식체를 유지합니다.

## 실행 도구 및 스크립트

- **입력 전처리 및 사전 점수 측정**:
  ```bash
  bun run scripts/prepare-humanize-input.ts --text "<입력텍스트>" [--run-dir "_workspace/YYYY-MM-DD-001"] [--genre essay|column|report|blog]
  # 또는 파일 지정
  bun run scripts/prepare-humanize-input.ts --file "<입력파일경로>" [--run-dir "_workspace/YYYY-MM-DD-001"]
  ```
- **사후 변경률 게이트 검증**:
  ```bash
  bun run scripts/verify-change-rate.ts --before <원문파일> --after <윤문본파일> [--ignore-markup]
  ```

## 단계별 실행 절차

### 1단계: 입력 텍스트 확보 및 전처리

1. 사용자가 제공한 텍스트 또는 파일 경로 확인.
2. 장르 파악 (칼럼 `column`, 리포트 `report`, 블로그 `blog`, 에세이/일반 `essay`).
3. `bun run scripts/prepare-humanize-input.ts`를 실행하여 텍스트 정제(비가시 문자 제거, 정규화) 및 정량 점수, `route_hint` 확인.

### 2단계: 경로별 윤문 수행

- **Light 경로 (티가 거의 없는 글)**:
  - 진단 생략, 보수적 강도로 단일 윤문 수행.
  - 고칠 곳이 거의 없으면 원문의 장점을 살리고 불필요한 수정을 자제.
- **Standard 경로 (보통의 AI 초안)**:
  - 글 전체의 지배 패턴(3~6개)을 먼저 파악.
  - 아래 우선순위 순서대로 문단 단위 윤문 수행.
- **Heavy 경로 (중증 AI 슬롭 또는 장문)**:
  - 전체 지배 패턴 상세 진단 작성 -> 겨냥 윤문 -> 엄격한 자체 검증 수행.

### 윤문 적용 우선순위

1. **D (AI 관용구)**: "결론적으로", "시사하는 바가 크다", hype 어휘 등 불필요한 수식 제거
2. **A (번역투)**: "~를 통해", "~에 대해", "~에 있어", "가지고 있다", 이중 피동(~되어지다) 개선
3. **I (형식명사)**: "~인 것이다", "~할 필요가 있다" 환원
4. **G (Hedging)**: 과도한 완곡어구 정리
5. **H (접속사)**: 문두 "또한", "따라서", "즉", "나아가" 과다 사용 제거
6. **F (수식·중복)**: -적, -성, -화 명사 나열 및 중복 수식 단순화
7. **B (영어 인용)**: 불필요한 괄호 병기 축소
8. **C/J (구조 및 서식)**: 이모지 남발 제거, 연결어미 뒤 쉼표(-고, -며, 등) 삭제
9. **E (리듬·문장 길이)**: 균일한 문장 길이를 단문과 복문으로 변주, 종결어미 다양화

### 3단계: 변경률 및 게이트 검증

1. 윤문본을 `final.md` 등에 저장 후 `bun run scripts/verify-change-rate.ts` 실행.
2. 결과 판정:
   - **0 (OK)**: 변경률 30% 미만 -> 통과
   - **1 (WARN)**: 변경률 30%~50% -> 과윤문 경고, 변경 내역 재검토
   - **2 (ABORT)**: 변경률 50% 이상 -> 과윤문 강제 중단, 롤백 후 보수적 강도로 재실행

### 4단계: 자체검증 6항 체크리스트

1. [ ] 고유명사, 숫자, 날짜, 인용문이 원문과 100% 일치하는가?
2. [ ] 변경률이 허용 범위(30% 이하) 이내인가?
3. [ ] 원문의 장르와 톤(칼럼/리포트/에세이)이 유지되었는가?
4. [ ] 원문의 격식체/경어법(register)이 일관되는가?
5. [ ] 핵심 S1 패턴(번역투 피동, AI 특유 관용구, 이모지 등)이 모두 해소되었는가?
6. [ ] 원문에 없던 비유나 새로운 내용이 임의로 추가되지 않았는가?

### 5단계: 최종 결과 보고

사용자에게 아래 항목을 간결하고 명확하게 전달합니다:

1. **상태 요약**: 완료 상태, 변경률, 품질 등급(A/B/C/D), 통과 여부
2. **윤문본 전문**: 마크다운 블록으로 출력
3. **핵심 개선점**: 주요 수정 항목 3~5건 (수정 전 -> 수정 후 비교)
